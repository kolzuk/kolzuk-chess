# ♟️ kolzuk-chess

**Шахматный движок и HTTP-бэкенд на Scala.** Проект с нуля реализует всю «математику» шахмат: хранение позиции, генерацию всех легальных ходов, оценку позиции и поиск лучшего хода — а затем отдаёт это наружу как удобное REST API.

> Проще говоря: это «мозг» для шахмат. Вы присылаете ему позицию на доске — он отвечает, какие ходы возможны и какой из них лучший.

## 🧠 Зачем это сложно инженерно

Шахматы кажутся простой игрой, но написать движок с нуля — это серьёзная инженерная задача. Вот где здесь настоящая сложность:

1. **Битовые доски (bitboards).** Позиция хранится не как «массив клеток», а как 12 чисел по 64 бита. Каждый бит — это одна клетка доски. Такое представление позволяет проверять ходы целых групп фигур одной машинной операцией (`AND`, `OR`, сдвиг), а не циклом. Это тот же приём, что используют топовые движки вроде Stockfish.

2. **Магия работы с битами.** Чтобы быстро находить фигуры на битовой доске, используется алгоритм [**De Bruijn sequence**](https://www.chessprogramming.org/BitScan) — математический трюк, который за одно умножение вычисляет позицию младшего бита.

3. **Генерация ходов «слайдеров».** Для ладьи, слона и ферзя ходы вычисляются через предрассчитанные «лучи» (rays) во все 8 направлений с учётом фигур-препятствий.

4. **Поиск с alpha-beta отсечением.** Чтобы не перебирать миллиарды вариантов, применяется алгоритм [**alpha-beta pruning**](https://www.chessprogramming.org/Alpha-Beta) — он «отсекает» заведомо плохие ветки, ускоряя поиск в разы. Плюс — сортировка ходов (сначала шахи и взятия), чтобы отсечение работало эффективнее.

5. **Корректность доказана математически.** Правильность генератора ходов проверяется тестами [**perft**](https://www.chessprogramming.org/Perft) — эталонными позициями, для которых точно известно число ходов на N шагов вперёд (вплоть до **4 865 609** позиций).

6. **Функциональный подход и чистая архитектура.** Класс доски [`Board`](modules/common/src/main/scala/common/core/model/Board.scala:12) неизменяемый (immutable) — каждый ход создаёт новую доску, а не портит старую. Это делает код безопасным и предсказуемым.

## 🏗️ Архитектура

Проект разбит на **три независимых SBT-модуля** — это классический принцип разделения ответственности.

```
┌─────────────────────────────────────────────────────────┐
│                      chess-engine                          │
│   HTTP-сервер (ZIO HTTP) + вся игровая логика:            │
│   MoveGenerator · MoveSearcher · Evaluator                 │
└───────────────────────────┬───────────────────────────────┘
                            │ зависит от
                            ▼
┌─────────────────────────────────────────────────────────┐
│                        common                              │
│   Общие модели и утилиты:                                  │
│   Board · Figure · Move · Bitboards · FEN-парсер           │
│   + DTO для API                                            │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                      public-api                            │
│   Заготовка для будущего публичного шлюза                  │
└─────────────────────────────────────────────────────────┘
```

- **`common`** — «сердце»: модели предметной области (доска, фигуры, ходы), битовые доски и парсер FEN. Не знает ничего про HTTP.
- **`chess-engine`** — «мозг» + веб-сервер: генератор ходов, оценщик позиции, поиск лучшего хода и REST API поверх них.
- **`public-api`** — заготовленный модуль для внешнего API-шлюза.

Внутри `chess-engine` логика собрана из трёх компонентов, каждый описан через **интерфейс + реализацию** (dependency injection на слоях ZIO):

| Компонент | Интерфейс | Задача |
|-----------|-----------|--------|
| Генератор ходов | [`MoveGenerator`](modules/chess-engine/src/main/scala/chessengine/core/movegenerator/MoveGenerator.scala:10) | найти все легальные ходы |
| Оценщик позиции | [`Evaluator`](modules/chess-engine/src/main/scala/chessengine/core/evaluator/Evaluator.scala:7) | оценить, кто выигрывает (по материалу) |
| Поиск | [`MoveSearcher`](modules/chess-engine/src/main/scala/chessengine/core/search/MoveSearcher.scala:8) | выбрать лучший ход через alpha-beta |

Компоненты связываются в [`Main`](modules/chess-engine/src/main/scala/chessengine/Main.scala:9) через ZIO-слои, а сервер поднимается в [`ChessEngineServer`](modules/chess-engine/src/main/scala/chessengine/api/ChessEngineServer.scala:13).

## 🔬 Как устроен движок «под капотом»

### 1. Позиция → FEN

Любая шахматная позиция кодируется строкой в формате **FEN** (Forsyth–Edwards Notation). Например, стартовая позиция:

```
rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1
```

Парсер [`ForsythEdwardsNotationUtils`](modules/common/src/main/scala/common/core/utils/ForsythEdwardsNotationUtils.scala:17) умеет переводить строку в объект доски и обратно — это «язык», на котором клиент общается с движком.

### 2. Доска → битовые доски

Из обычной доски строятся **12 битбордов** (по одному на каждый тип фигуры каждого цвета) в [`BitboardRepresentation`](modules/common/src/main/scala/common/core/model/bitboards/BitboardRepresentation.scala:8). Все операции с ходами — это быстрые побитовые вычисления в [`BitboardOperations`](modules/common/src/main/scala/common/core/model/bitboards/BitboardOperations.scala:7).

### 3. Генерация ходов

[`MoveGeneratorLive`](modules/chess-engine/src/main/scala/chessengine/core/movegenerator/MoveGeneratorLive.scala:9) для каждой фигуры генерирует «полулегальные» ходы, а затем отсеивает те, после которых собственный король оказывается под шахом — так остаются только по-настоящему легальные ходы.

### 4. Поиск лучшего хода

[`MoveSearcherLive`](modules/chess-engine/src/main/scala/chessengine/core/search/MoveSearcherLive.scala:7) строит дерево вариантов на заданную глубину и применяет **alpha-beta pruning** с сортировкой ходов. Оценка листьев дерева берётся у оценщика [`EvaluatorLive`](modules/chess-engine/src/main/scala/chessengine/core/evaluator/EvaluatorLive.scala:6), который сейчас считает материальный перевес (пешка = 100, конь/слон = 300, ладья = 500, ферзь = 1000).

## 🌐 API и примеры работы

Все запросы — `POST`, тело в формате JSON. Ниже — три доступных эндпоинта.

### 1. Все возможные ходы — `POST /api/all-possible-moves`

Возвращает список всех легальных ходов в текущей позиции (в формате UCI, например `e2e4`).

**Эндпоинт:** [`AllPossibleMovesEndpoint`](modules/chess-engine/src/main/scala/chessengine/api/endpoints/AllPossibleMovesEndpoint.scala:16)

**Запрос:**

```bash
curl -X POST http://localhost:8080/api/all-possible-moves \
  -H "Content-Type: application/json" \
  -d '{
    "fen": "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1"
  }'
```

**Ответ:**

```json
{
  "moves": [
    "a2a3", "a2a4", "b2b3", "b2b4", "c2c3", "c2c4",
    "d2d3", "d2d4", "e2e3", "e2e4", "f2f3", "f2f4",
    "g2g3", "g2g4", "h2h3", "h2h4", "b1a3", "b1c3",
    "g1f3", "g1h3"
  ]
}
```

> В стартовой позиции у белых ровно **20 ходов** — 16 пешечных и 4 коней. Это классическая эталонная величина.

---

### 2. Лучший ход — `POST /api/best-move`

Движок анализирует позицию на глубину `depth` и возвращает лучший ход (или несколько равнозначных).

**Эндпоинт:** [`BestMovesEndpoint`](modules/chess-engine/src/main/scala/chessengine/api/endpoints/BestMovesEndpoint.scala:16)

**Запрос:**

```bash
curl -X POST http://localhost:8080/api/best-move \
  -H "Content-Type: application/json" \
  -d '{
    "fen": "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1",
    "depth": 3
  }'
```

**Ответ:**

```json
{
  "moves": ["b1c3", "g1f3"]
}
```

> `depth` — на сколько ходов вперёд «думает» движок. Чем больше глубина, тем сильнее игра, но тем дольше вычисления.

---

### 3. Сделать ход — `POST /api/make-move`

Применяет ход к позиции и возвращает новую позицию в формате FEN.

**Эндпоинт:** [`MakeMoveEndpoint`](modules/chess-engine/src/main/scala/chessengine/api/endpoints/MakeMoveEndpoint.scala:15)

**Запрос:**

```bash
curl -X POST http://localhost:8080/api/make-move \
  -H "Content-Type: application/json" \
  -d '{
    "fen": "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1",
    "move": "e2e4"
  }'
```

**Ответ:**

```json
{
  "fen": "rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq - 0 1"
}
```

> Пешка сходила с `e2` на `e4`. В ответе — новая позиция, где ход перешёл к чёрным (`b` в FEN).

### Типичный сценарий использования

```
1. Клиент присылает позицию  →  /api/all-possible-moves  →  видит доступные ходы
2. Клиент просит совет         →  /api/best-move          →  получает сильнейший ход
3. Клиент делает ход           →  /api/make-move          →  получает новую позицию
4. Повторить с шага 1
```

Так на базе этого движка можно построить полноценную шахматную игру или бота.

## ✅ Тестирование (perft)

Корректность генератора ходов проверяется методом **perft** — подсчётом числа всех возможных позиций на N ходов вперёд для эталонных позиций из [Chess Programming Wiki](https://www.chessprogramming.org/Perft_Results). Если хоть одно правило реализовано с ошибкой, числа не сойдутся.

Примеры проверок из [`MoveGeneratorTest`](modules/chess-engine/src/test/scala/chessengine/core/movegenerator/MoveGeneratorTest.scala:11):

| Позиция | Глубина | Ожидаемое число позиций |
|---------|---------|-------------------------|
| Стартовая | 5 | 4 865 609 |
| Kiwipete | 4 | 4 085 603 |
| Позиция №5 | 4 | 2 103 487 |

Запуск всех тестов:

```bash
sbt test
```

Тесты автоматически прогоняются в CI через [GitHub Actions](.github/workflows/ci.yml) на каждый push и pull request.
